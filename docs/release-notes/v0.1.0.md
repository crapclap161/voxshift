# VoxShift v0.1.0 — Reliability Release

**A release about dependability.** The whole code base, the audio pipeline and the release tooling were reviewed, and
the problems found were fixed and covered by tests. There are no new audio features, nothing was removed, and your
settings and soundboards carry over unchanged.

## What's improved

### Soundboard
- **A sound that failed to load recovers on the next click.** Previously the failure was remembered and one more click
  was needed before VoxShift tried again.
- **Double-clicking a sound that is still loading no longer starts it twice.**
- **Sounds that only play in your headphones** (when the virtual cable is not running) are now shown as playing and
  can be stopped with a second click.
- **Very large WAV files** no longer risk running out of memory: the five-minute limit is applied while the file is
  decoded, not afterwards.
- **An empty WAV file** is reported as containing no audio instead of silently playing nothing.
- **Importing more than 500 files at once** tells you that only the first 500 were added.
- The number of simultaneously playing sounds stays bounded even when sounds are started faster than audio is
  rendered or while the output device is unavailable.

### Audio engine
- **No doubled sounds:** the headphone monitor is re-checked when its device becomes the VRChat output.
- **No restart loop:** an application that Windows does not let VoxShift query (for example one running as
  administrator) no longer causes the capture to restart every second.
- A microphone with an unsupported format no longer leaks resources on every retry, and errors on the audio thread
  are written to the log instead of being ignored.
- Device and application lists no longer hang when requested during shutdown.

### Interface
- **Keyboard shortcuts work from the soundboard too:** `Ctrl+1`, `Ctrl+2`, `Ctrl+T`, `Ctrl+B` and `F5` no longer
  stop working after you click the soundboard.
- **The fourth status tile is now called CABLE** (it was *VRCHAT*). It shows whether VoxShift is sending into the
  virtual cable. VoxShift cannot see whether VRChat itself is running, so the old name promised too much.
- Dialogs opened from VR Controller Mode appear on top of that window.

### Documentation
- The README was rewritten: requirements, a table of what each mode sends, all shortcuts and preferences, known
  limitations and a longer troubleshooting list. It also corrects one point: the global hotkey is **off until you
  enable it** under *Preferences → Hotkey*.
- New developer guide: [docs/development.md](https://github.com/crapclap161/voxshift/blob/main/docs/development.md).

## Good to know
- **Updating:** replace the EXE. Nothing needs to be migrated.
- **Requirements are unchanged:** Windows 11 x64 and the free [VB-CABLE](https://vb-audio.com/Cable/) driver.
- **Breaking changes:** none.
- **Signature:** the executable is signed with the VoxShift release key, the same self-signed key as v0.0.8 and
  v0.0.9. Windows does not trust a self-signed certificate on its own and shows no verified publisher, so the
  SmartScreen prompt can still appear. See the *Digital signature* section below.

## Known limitations
- Application capture works per program, not per browser tab, and needs Windows 11.
- Copy-protected (DRM) audio may be delivered as silence by Windows.
- Sounds are limited to five minutes each; OGG and Opus files are not supported.
- Behaviour that depends on real audio hardware (unplugging devices, the virtual cable, VRChat itself) is checked
  manually; the automated tests cover the mixing logic and a device-free run of the real executable.
