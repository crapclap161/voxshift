# VoxShift v0.0.6 — Window Closing & System Tray Fix

Clicking the **X** button no longer causes error dialogs. VoxShift now asks what you want: **minimize to the system
tray**, **quit**, or **cancel**, and you can make that choice permanent.

## Fixed
- Fixed the two *"An unexpected error occurred: Cannot set Visibility to Visible or call Show, ShowDialog, Close, or
  WindowInteropHelper.EnsureHandle while a Window is closing"* dialogs when clicking the close button.
- Fixed unsafe window closing operations: windows were closed and hidden from inside their own `Closing` handlers,
  which WPF forbids. Closing now only queues a request and everything else runs afterwards.
- Fixed shutdown and secondary window lifecycle problems (main window, docked soundboard, VR Controller window).
- Improved shutdown reliability: one coordinated shutdown that runs exactly once, whatever is clicked.
- Prevented duplicate error dialogs; errors are still written to the log.

## Added
- **Close confirmation dialog** – *What would you like to do with VoxShift?*
  - **Minimize to Tray**: hides VoxShift and the docked soundboard; microphone/application routing and the
    soundboard keep running.
  - **Quit VoxShift**: saves settings, stops all audio and closes every window and the process.
  - **Cancel**: nothing changes.
- **Configurable X-button behavior** – new setting **When clicking the X button**: *Always ask* (default),
  *Minimize to system tray*, *Quit VoxShift*.
- **Remember my choice** in the dialog (Cancel is never remembered).
- A one-time notice *"VoxShift is still running in the system tray."* the first time VoxShift hides into the tray.

## Improved
- **System tray:** **Show VoxShift** restores the right interface (never during shutdown); **Exit VoxShift** quits
  immediately without asking.
- **Window restoration:** the dock reappears next to the main window with its expanded/collapsed state and selected
  collection; no duplicate windows, no audio restart.
- **Docked soundboard cleanup:** it can no longer reopen or reposition itself while VoxShift is quitting.
- **VR Controller Mode:** its X still returns to the full interface (so nobody is locked out), now without lifecycle
  errors; minimizing to the tray and quitting work from VR mode too.
- **Resource cleanup:** idempotent, logged on failure, and the process always ends.
- **Error handling:** no error dialogs after shutdown started, none stacked on top of each other.

## How to use it
1. Click **X** on the VoxShift window and choose **Minimize to Tray**, **Quit VoxShift** or **Cancel**.
2. Tick **Remember my choice** to stop being asked, or change it any time under **When clicking the X button**
   in the options (*Always ask*, *Minimize to system tray*, *Quit VoxShift*).
3. From the tray icon, **Show VoxShift** brings the window back and **Exit VoxShift** quits.
